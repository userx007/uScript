# AT24C02 via CP2112 Plugin — Command Sequences

## Device Overview

The AT24C02 is a **2Kbit (256 × 8) I²C EEPROM**.

| Parameter | Value |
|---|---|
| Capacity | 256 bytes |
| Word address | 8-bit (single byte) |
| Page size | **8 bytes** (32 pages) |
| Write cycle time (tWR) | **5 ms max** |
| I²C address | `1010 A2 A1 A0` → 0x50–0x57 |
| Max clock | 400 kHz (1 MHz on -ULP variants) |

---

## I²C Address

| A2 | A1 | A0 | 7-bit | Write byte | Read byte |
|----|----|----|----|----|----|
| 0 | 0 | 0 | 0x50 | 0xA0 | 0xA1 |
| 0 | 0 | 1 | 0x51 | 0xA2 | 0xA3 |
| ... | | | ... | | |
| 1 | 1 | 1 | 0x57 | 0xAE | 0xAF |

---

## Open the Bus

```
CP2112.I2C open addr=0x50 clock=400000
```

Scan first if address pins are unknown:
```
CP2112.I2C scan
```

---

## Write Operations

### Byte Write — single byte at address `0x1A`

```
CP2112.I2C write 1A AB
```

Raw I²C sequence:
```
S | 0xA0 | A | 0x1A | A | 0xAB | A | P
     ^            ^           ^
  ADDR+W      word addr     data
```

> **Wait 5 ms after every write command** before the next bus access (tWR). Use `SCRIPT_DELAY=5` in the INI, or add explicit delays in your script.

---

### Page Write — up to 8 bytes starting at address `0x00`

```
CP2112.I2C write 00 0102030405060708
```

Raw sequence:
```
S | 0xA0 | A | 0x00 | A | 0x01 | A | 0x02 | A | ... | 0x08 | A | P
```

> The word address auto-wraps within the 8-byte page. Writing across a page boundary rolls over within that page — it does **not** spill into the next page. Always align the starting address to a page boundary (`0x00, 0x08, 0x10, ...`).

---

### Multi-Page Write — pages must be sent separately with tWR between each

```
# Page 0: bytes 0x00–0x07
CP2112.I2C write 00 0102030405060708

# ← wait 5 ms (SCRIPT_DELAY or inter-command pause)

# Page 1: bytes 0x08–0x0F
CP2112.I2C write 08 090A0B0C0D0E0F10

# Page 2: bytes 0x10–0x17
CP2112.I2C write 10 1112131415161718
```

---

### Bulk Write from File — program entire chip from binary file

```
CP2112.I2C wrrdf eeprom_image.bin:8:0
```

Format: `wrrdf filename:wrchunk:rdchunk`

- `wrchunk=8` — matches the AT24C02 page size exactly
- `rdchunk=0` — no read-back per chunk (write-only)

> Each 8-byte chunk becomes one page write transaction. Set `SCRIPT_DELAY=5` in the INI so the plugin pauses 5 ms between chunks, respecting tWR.

## Read Operations

### Current Address Read — re-read whatever address the internal pointer is at

```
CP2112.I2C read 1
```

Raw sequence:
```
S | 0xA1 | A | [data] | N | P
```

---

### Random Read — read 1 byte from address `0x1A`

```
CP2112.I2C wrrd 1A:1
```

Raw sequence (write address pointer, repeated-start, read):
```
S | 0xA0 | A | 0x1A | A | Sr | 0xA1 | A | [data] | N | P
```

---

### Sequential Read — read N bytes starting at address `0x00`

```
# Read 16 bytes from address 0x10
CP2112.I2C wrrd 10:16
```

```
# Read the entire 256-byte array in one shot
CP2112.I2C wrrd 00:256
```

Raw sequence for sequential read:
```
S | 0xA0 | A | 0x00 | A | Sr | 0xA1 | A | [d0] | A | [d1] | A | ... | [d255] | N | P
```

> The AT24C02 address counter wraps from `0xFF` back to `0x00` automatically — the device handles the full 256-byte rollover with no gaps.

---

### Read-Back Verify — write then immediately verify a page

```
# Write page at 0x08
CP2112.I2C write 08 DEADBEEFCAFEF00D

# Wait tWR (5 ms — via SCRIPT_DELAY or manual pause)

# Read back 8 bytes from the same address
CP2112.I2C wrrd 08:8
# Expected response: DEADBEEFCAFEF00D
```

---

### Write + Read in a Single `wrrd` — not directly supported

The AT24C02 requires a **Repeated Start** between the address-set write and the data read (standard random read protocol). The plugin's `wrrd` command does exactly this — it performs the write phase, then the read phase with a repeated-start, which matches the EEPROM's required transaction format perfectly.

---

## Acknowledge Polling (detect end of internal write cycle)

The AT24C02 NACKs its address during tWR. You can poll for completion instead of waiting a fixed 5 ms:

```
# Issue a zero-byte write probe — device ACKs only when ready
CP2112.I2C write
# Repeat until it stops failing (ACK received)
```

> In a script, use a tight loop of zero-byte writes. The first one that succeeds (no NACK / no error return) signals that the write cycle is complete.

## Full Workflow — Script File Example (`at24c02_init.txt`)

```
# at24c02_init.txt — stored in ARTEFACTS_PATH
# Writes known pattern across first 4 pages, then reads back

# Page 0: 0x00–0x07
write 00 0011223344556677
# Page 1: 0x08–0x0F  (SCRIPT_DELAY=5 handles tWR pause)
write 08 8899AABBCCDDEEFF
# Page 2: 0x10–0x17
write 10 DEADBEEFCAFEF00D
# Page 3: 0x18–0x1F
write 18 0102030405060708

# Read back all 32 bytes
wrrd 00:32
```

Execute with:
```
CP2112.I2C open   addr=0x50 clock=400000
CP2112.I2C script at24c02_init.txt
CP2112.I2C close
```

## Key Constraints Mapped to This Device

| Constraint | AT24C02 requirement | Plugin behaviour |
|---|---|---|
| Max write payload per transaction | **8 bytes** (page size) | `write` accepts up to 512 B — **you** must not exceed 8 B per call |
| `wrrdf` chunk size | Set `wrchunk=8` | Plugin sends one `write` transaction per chunk |
| Read length | Up to **256 bytes** (full array) | Plugin cap is 512 B — no issue |
| tWR between writes | **5 ms** | Set `SCRIPT_DELAY=5` in INI, or pace manually |
| Address rollover in page write | Wraps **within 8-byte page** | No plugin enforcement — align manually |
| Device address | 0x50–0x57 (A2:A0 pins) | Set via `open addr=0xNN` |
