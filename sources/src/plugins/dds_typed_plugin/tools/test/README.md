## How to use it

```
DDS_TYPED.CONFIG d=12 cf=./cyclonedds-loopback.xml pp=./libcustomer1_types.so \
    qf=./USER_QOS_PROFILES_Cyclone.xml qd=StatePattern \
    qt=Alarms__Actual_Alarm=AlarmPattern;*__acknowledgeAlarm=CommandPattern
```
```ini
QOS_PROFILE_FILE    = ./USER_QOS_PROFILES_Cyclone.xml
QOS_DEFAULT_PROFILE = StatePattern
QOS_TOPIC_PROFILES  = Alarms__Actual_Alarm=AlarmPattern;*__acknowledgeAlarm=CommandPattern
QOS_LIBRARY         = DDSDefaultQoSLibrary
```

The four INI keys correspond to `qf=`, `qd=`, `qt=` and `ql=` in `CONFIG`.

- **Profile choice per topic.** `qt=` is an ordered list of `topic=profile` rules. The topic can be an exact name or a glob like `*__acknowledgeAlarm`, and the first match wins. Topics that match no rule get `qd=`.
- **Profile QoS is used as-is.** A selected profile's writer, reader and topic QoS are applied unchanged, and `RELIABLE`/`HISTORY_DEPTH` are not layered on top. That way the endpoints behave like an application using the profile directly. A topic with no profile keeps the old behaviour.
- **No silent fallback.** A missing file, a wrong profile name, a malformed `qt=` or an unparseable file makes the driver refuse to open, with a specific message.
- **`LIST` shows the result.** Local endpoints appear as `vehicle/state{qos=DDSDefaultQoSLibrary::StatePattern}`.

## Limitations

- **Use `USER_QOS_PROFILES_Cyclone.xml`, not `USER_QOS_PROFILES_Consolidated.xml`.** Cyclone's provider rejects the Consolidated file because it lacks a `<dds>` root and has an empty `<deadline>`.
- **The `Default` profile is empty.** It means DDS defaults for every kind. Cyclone prints `Failed to get qos with name…` lines for the missing kinds, and that is expected.
- **Only writer, reader and topic QoS are applied.** Your file defines nothing else. Publisher, subscriber and participant QoS (for example partitions) would need a small extension.
- **INI values need care with `;`.** Don't put whitespace before a `;`, because the INI parser then treats it as a comment.
